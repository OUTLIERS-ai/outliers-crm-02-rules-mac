Layer 2 · The Rules

Who is this?

Every clever feature you add later has to start by asking that question. If it gets the wrong answer, everything after it is wrong too, and nothing reports it.

What the last layer left you with

You have a folder with one file per person in it. It works, and it will keep working right up until the moment 2 files describe the same human being. Nothing in your system currently prevents that, notices it, or could tell you which of the 2 is right.

What this layer builds

This layer gives your CRM a way to know that one person is one person, however their name happens to be written down that day. It also writes down the shape a record has to follow, in a form software can check, so a broken record gets refused as it is written rather than found months later.

Layer 2 · How it works

How it works

2 ideas, and the first one is the whole layer.

1. One identifier decides who someone is

A name is not an identifier. Names repeat, people change them, and the same person gets written down 4 different ways by 4 different sources. What you need is one detail per person that is unique to them and does not change: usually a profile link, sometimes an email address.

Your system now picks that identifier first and treats everything else as decoration. Every other spelling of their name is kept in a list beside it, so when any of those spellings turns up later, the system knows where it belongs.

Why it never guesses. If a name could be 2 different people, the system refuses to answer rather than picking one. That is deliberate. Consider the alternative: a wrong merge welds 2 people's histories together, silently and permanently, and you will not find out until you say the wrong words to someone.

2. The shape of a record, written down where software can check it

A rule that nothing checks will be broken without anyone noticing. Your system now keeps a short description of what a record must contain, and anything writing to your CRM has to satisfy it first. A record that is missing something gets refused at the moment it is written.

The same file also keeps the list of words your system is allowed to use for each idea, so one idea never ends up with 5 names for it. It sounds fussy. It is what makes the difference between a CRM you can ask questions of and a folder of notes.

And 3 rules it never breaks

  • Never delete a person. People come back. Records get set aside, not destroyed.
  • Never store anything sensitive about someone's health, beliefs or politics.
  • Never let an automation speak as you. That one becomes machinery in Layer 6.

Layer 2 · Before you start

Before you start on a Mac

Everything in this guide is typed into Terminal, the Mac's window for typing commands instead of clicking. Press Command and Space together, type Terminal, and press Return.

This layer needs Python and git, which you set up for Layer 1 (its page "Before you start on a Mac"), and the layers before this one. It installs no add-ons, so it works with either Python a Mac may have.

How to type the lines

Where this guide shows several lines in a black box, type them one at a time: type the first, press Return, wait for it to finish and give you a fresh line, then type the next. The installer asks you questions. Each offers an answer in [square brackets]; press Return to take it, or type your own and press Return.

Where your CRM is

Layer 1 made your CRM at ~/CRM: a folder called CRM in your home folder (the folder with your name and the house picture in Finder's sidebar). If you chose another folder in Layer 1, put your own folder wherever a line in this guide says ~/CRM. The installer finds your CRM by itself either way.

Apple Silicon or Intel (the 2 kinds of chip a Mac can have; the Apple menu, then About This Mac, shows yours): the steps are the same on both, and both were tested.

Tried only on test Macs. Every step in this guide and in the instructions file of the layer's download was tried on test Macs (Macs GitHub rents out by the minute to run a script, not a person's own Mac, and not yours), never on a real Mac, except 3: the box asking to install the developer tools, which cannot appear on a test Mac; python3 identity.py who "<their profile link>", because it is a pattern: you type your own person's profile link where is; python3 identity.py who, because you type it with the nickname you add to the record yourself. The last pages list every line and what happened to it.

Layer 2 · Install

Build it

3 lines, typed into Terminal. The last one asks you a few questions so what you get is yours, then does the work.
git clone https://github.com/OUTLIERS-ai/outliers-crm-02-rules-mac
cd outliers-crm-02-rules-mac
python3 install.py

This layer needs Layer 1 already installed. It finds your CRM by itself and will tell you politely if it cannot.

What it asks you, and why

QuestionWhat it changes
Which detail will you always have for someone?A profile link, an email address, or a phone number. Whichever you always end up with. This becomes how your system tells one person from another.
Do you keep personal contacts in here too?Friends and family often end up in the same system. If you say yes, they get marked as personal, and nothing commercial will ever touch them.

What you end up with

  • A written description of what a record must contain, in a file you can read and change.
  • A tool that answers who is this? for any name, link or address you give it.
  • Every record now carries the list of other names that same person is known by.

Layer 2 · Finishing

Now use it

Ask your system who somebody is, 2 different ways, and watch one record come back.

Give your system the same person twice, written 2 different ways. Use their full name one time and their profile link the other. Pick a person of your own whose record has a profile link: Rowan Ashdown, the made-up person Layer 1 put in your CRM, has no link, on purpose.

The tools this layer installed live in a folder called _engine inside your CRM. In Terminal, go there first, then type the next 2 lines (if your CRM is not at ~/CRM, put your own folder in the cd line):

cd ~/CRM/_engine
python3 identity.py who "Rowan Ashdown"
python3 identity.py who "<their profile link>"

Put your person's name in place of Rowan Ashdown, and their profile link, copied from their record, in place of <their profile link>.

Both print the same record. Now open that person's file in Obsidian. Near the top is a line beginning aliases:. Add their nickname on a new line beneath it, save, and run python3 identity.py who again with the nickname. It finds them.

Every layer above this one depends on doing that reliably, thousands of times, without a human checking.

If you already had something like this

A test rather than an instruction. Take 2 records in your existing system that you suspect are the same person, and work out which one is correct. If you cannot do that quickly and confidently, this layer is doing real work for you.

What this layer leaves unsolved

Your records now have a shape and an identity, but nothing fills them in. Worse, the obvious details to write down about a person go out of date on their own: someone's job title is correct right up until they change roles, and nothing in the record knows that happened.
